3. ARQUITETURA DE DADOS E MULTI-TENANCY
Objetivo

Organizar e proteger os dados de várias empresas dentro do mesmo sistema.

Banco de dados:

PostgreSQL

Modelo escolhido:

Banco único Multi-Tenant

Cada registro possui vínculo com a empresa.

Exemplo:

Consulta:

id: 100

empresa_id: 5

Paciente:
João Silva

Data:
20/07

Horário:
14:00

A empresa só acessa seus próprios dados.

Principais entidades:
Empresa

Guarda:

nome;
configurações;
plano.
Usuário

Guarda:

login;
senha;
permissões.
Profissional

Guarda:

nome;
especialidade.
Consulta

Guarda:

paciente;
telefone;
data;
horário;
status.
Notificação

Guarda:

mensagem enviada;
horário;
status.
